Microsoft Zero Trust Workshop - Infrastructure

15 November 2026Doc update+58 / −19 lines

In brief

The guidance now defines infrastructure services more broadly, explains why infrastructure security matters, and describes an actionable First/Then/Next implementation backlog. It also reorganizes implementation areas covering posture, workloads, vulnerabilities, access, baselines, and runtime monitoring.

What security teams need to know

Administrators can use the revised workshop guidance to identify infrastructure security gaps and prioritize remediation projects. No required action is stated.

Microsoft Zero Trust Workshop - Infrastructure | Microsoft Learn

In a Zero Trust architecture, infrastructure security focuses on protectingInfrastructure provides the foundational computecompute, platform, storage, database, API, and platform resourcesmanagement services that host applications and servicesbusiness workloads. The Infrastructure workshop pillar helps organizations reduce implicit trust by continuously assessing, hardening, protecting, and monitoring infrastructure across multicloudcloud, multicloud, hybrid, and on-premises environments. Rather than implicitly trusting infrastructure, this pillar ensures that servers, containers, storage, and platform services are continuously assessed, hardened, and monitored under an assume-breach mindset.

Infrastructure pillar guidance focuses on managing security posture, protecting workloads at runtime, governing infrastructure configurations, controlling administrative access, and integrating infrastructure signals into security operations.

Workshop implementation

The Infrastructure workshop coverspillar helps organizations identify security gaps and create a prioritized implementation roadmap for infrastructure governance, posture management, workload protection, vulnerability remediation, and security operations.

The Infrastructure workshop pillar corresponds to the implementation areas summarizedInfrastructure technology defined in the table.Microsoft Security Adoption Framework (SAF).

Why focus on infrastructure?

Infrastructure misconfigurations, excessive administrative access, unpatched vulnerabilities, exposed services, and gaps in runtime monitoring can create paths to critical resources. The Infrastructure Workshop applies the Zero Trust principles of verify explicitly, use least privilege, and assume breach throughout the infrastructure lifecycle.

The expected output is an actionable backlog of infrastructure projects prioritized into First, Then, and Next based on organizational risk, dependencies, implementation effort, user impact, coverage, and readiness.

These areas summarize the Infrastructure workshop pillar. Use the detailed Infrastructure project guidance to review individual projects and implementation considerations.

How to use the Infrastructure Workshop

Use the web-based Workshop with infrastructure, cloud platform, security architecture, engineering, compliance, application, identity, network, and security operations stakeholders. For each relevant project:

  • Review the project objective and applicability to your environment.
  • Record the current status, notes, decisions, owners, and known dependencies.
  • Consider licensing, implementation effort, user impact, technical prerequisites, coverage, and cross-pillar dependencies.
  • Prioritize the project into First, Then, or Next and incorporate it into the implementation roadmap.

Open the Zero Trust Workshop and select the Infrastructure pillar.

Review the detailed Infrastructure project guidance for project-level information.

Assess your infrastructure posture

The Microsoft Zero Trust Assessment can provide programmatically generated findings for supported infrastructure configurations and activity data. Assessment results can help identify technical gaps and inform Workshop discussions, but the Assessment is complementary and is not required to conduct the Infrastructure Workshop. It does not evaluate every Infrastructure Workshop project.

Learn about the Zero Trust Assessment or get started with an assessment.

Who should participate?

  • Cloud platform, infrastructure, and solution architecture teams.
  • Security architecture, cloud security posture management, security operations, and incident response teams.
  • Server, container, storage, database, API, application platform, network, and identity teams.
