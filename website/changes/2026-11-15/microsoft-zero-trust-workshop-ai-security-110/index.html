Why focus on AI security?

AI systems can act on behalf of users, access large volumes of organizational data, invoke tools and APIs, retain memory, and produce content at scale. Weak ownership, excessive permissions, data oversharing, unapproved applications, insecure agent development, prompt injection, unsafe tool use, or insufficient monitoring can extend existing attack paths and create new ones. AI security therefore requires coordinated controls across identity, data, network, infrastructure, applications, DevSecOps, compliance, and security operations.

The expected output is an actionable backlog of AI security projects prioritized into First, Then, and Next based on risk, dependencies, implementation effort, user impact, licensing, regulatory requirements, and readiness.

Discover and assess AI applications, agents, models, and workloadsCreate a consolidated inventory across Microsoft and external platforms, including generative AI applications, agents, models, endpoints, workload identities, and local or shadow AI. Classify criticality and risk, assign owners, review findings, delegate remediation, and maintain continuous monitoring.
Register and govern AI agents throughout their lifecycleUse Agent 365 Registry or appropriate alternatives to register, classify, organize, publish, certify, activate, update, suspend, and retire agents. Assign sponsors and owners, establish governance templates and collections, synchronize external registries where supported, and automate registry management at scale.
Secure users, agent identities, and privileged administrationRequire supported user authentication, use dedicated agent identities rather than shared credentials, and apply least privilege, Conditional Access, risk-based controls, custom security attributes, identity governance, access packages, lifecycle workflows, and Privileged Identity Management to users, agents, workload identities, and administrators.
Govern agent access to resources, tools, and other agentsDefine approved resources, connectors, plugins, actions, MCP servers, and connected-agent scenarios. Scope permissions by agent purpose and risk, require approval for high-impact capabilities, apply Copilot Studio data policies where appropriate, and review access as agents and dependencies change.
Secure network paths and AI gatewaysRoute supported AI and agent traffic through identity-aware network controls such as Global Secure Access and secure AI or API gateways. Apply filtering, segmentation, rate limits, token controls, egress restrictions, prompt inspection, and protections for custom LLM endpoints and MCP servers.
Protect prompts, grounding data, outputs, and agent memoryUse Microsoft Purview capabilities such as Data Security Posture Management for AI, sensitivity labels, Data Loss Prevention, audit, collection policies, insider-risk controls, retention, and communication compliance. Reduce oversharing, protect grounding sources and embedded content, govern output-label inheritance, and define isolation, provenance, retention, deletion, and observability requirements for agent memory.
Manage AI application discovery and sanctioned useUse Microsoft Defender for Cloud Apps, endpoint controls, and organizational policy to discover generative AI applications and local agents, classify sanctioned and unsanctioned services, manage access, and block or restrict high-risk applications while preserving approved business scenarios.
Build and publish AI agents securelyEstablish secure-development requirements for identity, authorization, data handling, content safety, logging, memory, dependencies, deployment, and environment isolation. Require publishing and certification controls, review connector and tool risks, and align agent development with DevSecOps and software supply-chain practices.
Validate AI safety, security, and qualityUse content safety controls, Prompt Shields, adversarial and red-team testing, groundedness evaluations, runtime groundedness detection, data-quality rules, abuse testing, and defined release thresholds. Retest after material model, prompt, tool, data, memory, or configuration changes.
Protect AI infrastructure, models, and runtime environmentsDiscover AI workloads and models with cloud security posture capabilities, apply Azure Policy or equivalent governance, isolate sensitive infrastructure, protect AI services and agent runtimes, secure API and model endpoints, and monitor exposure, vulnerabilities, configurations, and runtime threats.
Log and monitor AI activityEnable audit and diagnostic logging for AI applications, agents, identities, services, prompts, responses, tool use, memory operations, model endpoints, and governance actions where supported. Define retention, privacy, data minimization, health monitoring, and access controls for AI telemetry.
Detect and respond to AI-specific threatsConnect AI data sources to Microsoft Sentinel, Microsoft Defender XDR, or another SIEM/XDR platform. Implement detections for prompt injection, anomalous agent behavior, risky AI use, data exposure, identity compromise, unsafe tools, and runtime attacks, and use dashboards, hunting queries, playbooks, and automated response with appropriate safeguards.
Continuously improve AI security postureEstablish recurring reviews for AI inventory, risk findings, DLP and insider-risk alerts, agent permissions, publishing controls, incident trends, model and agent evaluations, regulatory evidence, and remediation progress. Update policies and controls as AI capabilities, threats, and business use evolve.

These areas summarize the AI security workshop pillar. Use the detailed AI project guidance to review individual projects, dependencies, licensing considerations, and implementation guidance.

How to use the AI Workshop

Use the web-based Workshop with AI platform and application teams, agent makers, identity, data protection, networking, infrastructure, DevSecOps, security operations, privacy, legal, compliance, and business stakeholders. For each relevant project:

  • Review the project objective and applicability to your environment.
  • Record the current status, notes, decisions, owners, and known dependencies.
  • Consider licensing, implementation effort, user impact, data and regulatory requirements, technical prerequisites, coverage, and cross-pillar dependencies.
  • Prioritize the project into First, Then, or Next and incorporate it into the implementation roadmap.

Open the Zero Trust Workshop and select the AI pillar.

Review the detailed AI project guidance for project-level information.

Assess your AI security posture

The Microsoft Zero Trust Assessment complements the Workshop by evaluating supported AI security configurations and practices against security best practices. Use its findings as an additional input when validating the current state and prioritizing AI security projects. Assessment results do not replace the cross-functional inventory, risk, architecture, development, data, and operational review completed in the Workshop.

Learn about the Zero Trust Assessment.

  • AI platform owners, AI application teams, agent makers, data scientists, machine-learning engineers, application architects, and software engineering teams.
  • Identity, data governance, data protection, networking, infrastructure, cloud platform, endpoint management, and DevSecOps teams.
  • Security architecture, application security, cloud security, security operations, incident response, exposure management, and threat-intelligence teams.
