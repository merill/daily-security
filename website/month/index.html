Month in brief

SAF expands AI security, agent oversight, DevSecOps, and post-quantum planning

November’s substantive security guidance expansion puts AI systems, agentic operations, software delivery, and cryptographic migration into a common Security Adoption Framework (SAF) planning path. New Zero Trust material defines seven AI control areas and bounded-agent practices, while new DevSecOps and post-quantum pages add implementation and dependency-planning routes. Updated Secure Future Initiative guidance sharpens identity and secrets priorities around phishing-resistant authentication, managed identities, lifecycle automation, and exposed-secret remediation.

  • Zero Trust · AI and agents
    Zero Trust adds a seven-area control model for securing AI

    New guidance covers securing AI applications, agents, identities, models, data, tools, and infrastructure across seven control areas, from risk assessment and access control through monitoring and response. Administrators gain a basis for AI inventories, lifecycle governance, least-privilege design, data protection, secure deployment, and activity monitoring.

  • Zero Trust · AI and agents
    SAF defines governance boundaries for agent-assisted security operations

    The new conceptual page for AI-assisted and agentic security operations adds governance, human oversight, bounded automation, measurable outcomes, and SAF-aligned implementation paths. Security teams can use it to structure workflows, assign accountability, and define approval and rollback boundaries.

  • Zero Trust · Strategy and deployment
    Post-quantum guidance starts with cryptographic dependency discovery

    New SAF guidance covers identifying vulnerable cryptographic dependencies, planning quantum-resistant replacements, and maintaining readiness as standards and threats evolve across identity, applications, infrastructure, communications, IoT/OT, and supply-chain integrations. It supports dependency discovery and phased planning where migration lead times and harvest-now, decrypt-later risk matter.

  • Zero Trust · Strategy and deployment
    The DevSecOps workshop turns software-delivery gaps into a backlog

    New Zero Trust Workshop guidance aligns the DevSecOps pillar with SAF’s Development Security discipline, defines expected roadmap outputs, and focuses implementation on repository governance, developer access, secrets, and code review. Administrators can use it to identify gaps and prioritize an implementation backlog.

  • Secure Future Initiative · Identity and access
    SFI identity guidance prioritizes phishing resistance and secret lifecycle controls

    Updated Secure Future Initiative guidance centers on reducing identity compromise, token abuse, and exposed-secret risk. Its priorities include phishing-resistant authentication, reduced static credentials through managed identities, automated key and secret lifecycle controls, standardized SDKs, and faster credential remediation. Administrators can use it to review privileged-access, credential, secret, and key-management practices.

For security architects and administrators

Administrators can turn this material into four workstreams: inventory AI systems and cryptographic dependencies; define agent approval, rollback, and accountability boundaries; assess the developer-to-production path; and review phishing resistance, managed identities, secret rotation, and exposed-secret detection.
